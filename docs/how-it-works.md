# Як працює аналізатор

## Контракт етапу конвеєра

Основний інтерфейс:

```python
from cefr_analyzer import Analyzer, analyze
from cefr_analyzer.scoring import ScoringConfig

result = analyze(text="I like reading.")

# Для пакетної обробки словники завантажуються лише один раз:
analyzer = Analyzer(config=ScoringConfig(include_automatic=False))
result = analyzer.analyze(text=transcript, words=dataframe, ignore_terms=["Alice"])
```

`text` — `str` або `None`. `words` — pandas DataFrame, словник колонок парсера
`{"word": [...], "time_code": [...]}` однакової довжини або список словників
з обов'язковими колонками `word` (рядок) і `time_code` (будь-яке значення).
Додаткові колонки ігноруються. Pandas не імпортується аналізатором:
достатньо методу `to_dict(orient="records")`.

Таймкод може бути числом секунд, рядком `00:01:02.300` або словником
`{"start": 1.2, "end": 1.6}`. Аналізатор зберігає значення без перетворення.
Для серіалізації JSON вони мають бути JSON-сумісними; об'єкти `pd.Timestamp`
слід перетворити на рядки до виклику. Порядок рядків є порядком транскрипції:
сортування за часом не виконується.

Якщо текст відсутній, він утворюється з колонки `word` через пробіл.
Якщо надано текст і таблицю, перевіряється рівність нормалізованих токенів:
регістр, пунктуація та підтримувані скорочення не заважають зіставленню.
Пропущені або зайві слова викликають `ValueError`. Часові позначки не
прив'язуються приблизно до невідповідного тексту. Одна комірка `word`
може містити кілька слів; усі вони отримають таймкод цього рядка.

Порожній текст або недостатня кількість надійних лексичних свідчень дають
`assessment.level = null`, а не штучний рівень A1.

## Послідовність аналізу

1. Токенізація зі збереженням позицій у початковому тексті.
2. Розкриття підтримуваних скорочень і перевірка таймкодів.
3. Явне виключення назв та імен через `ignore_terms`; числа також не є лексикою.
4. Пошук словникових виразів, включно з відмінюванням дієслова та розривами.
5. Аналіз слів, що не є компонентами знайдених виразів.
6. Незалежний граматичний розбір цілих допоміжних ланцюжків.
7. Розрахунок поширеності надійних ознак та загального рівня.

Модулі відповідають цим крокам: `text.py`, `morphology.py`, `phrases.py`,
`grammar.py`, `scoring.py`. `lexicon.py` зберігає дані та походження оцінок,
`sources.py` містить адаптери джерел. `analyzer.py` об'єднує результати.
Класи `Analyzer` і `Lexicon` дозволяють повторно використовувати завантажені
словники; окремий framework чи модель NLP не потрібні.

Граматичні групи слів зберігаються в `cefr_analyzer/data/grammar_words.json`:
`be`, `have`, `modals`, `skip`, `adjectival`, `objects`, `determiners`,
`clause_stops`, `inversion`. Значення — непорожні JSON-масиви слів у нижньому
регістрі. Завантажувач `word_groups.py` перевіряє формат і перетворює масиви
на незмінні `frozenset`. Файл читається під час імпорту модуля граматики;
після редагування потрібно перезапустити процес. Перебудовувати CEFR-словники
не потрібно. Ці групи керують розпізнаванням, а не присвоюють рівні CEFR.

## Токени й нормалізація

Розпізнаються слова, апострофи та числа; Unicode-літери зберігаються цілими,
щоб `café` не перетворювалося на інше слово `caf`. Це не визначення мови:
аналізатор очікує англійський текст, а невідому лему залишає без CEFR. Межі речень задає
пунктуація `. ! ? ; :`, а не переведення рядка. Вставка або видалення
окремих переносів рядків між словами не змінює оцінку, знайдені ознаки
та розподіли. Символьні позиції змінюються відповідно до нового тексту.

`can't → can not`, `I'm → I am`, `we've → we have` тощо. Два токени
скорочення мають однаковий вихідний символьний діапазон і таймкод.
`he's been → he has been`; в інших підтримуваних займенникових `'s`
обирається `is`. Неоднозначні `'d` без достатнього контексту не стають
впевненими граматичними ознаками. Присвійне `John's` дає основу `john`.
Скорочення `gonna`, `wanna`, діалектні й довільні ASR-форми спеціально
не виправляються. Межа речення не відновлюється за новим рядком.

## Слова та морфологія

Для кожного слова перевіряються точний запис, таблиця відомих словоформ
і регулярні кандидати `-s/-es/-ies`, `-ed`, `-ing`, `-er/-est`.
Підтримано повернення кінцевого `e`, подвоєної приголосної, `i → y`
та `y → ie` для дієприкметників на зразок `dying → die`.
Регулярний кандидат приймається тільки для відомої леми з відповідною
частиною мови. Суфікс невідомого слова не створює нової леми або CEFR.

`went → go`, `children → child`, `written → write` надходять із таблиці
форм OpenJam. Відповідність `word_id → id` перевіряється при побудові;
нерозв'язаний ID є помилкою, а не пропущеним записом.
Точна словоформа та її єдина інфлекційна основа (`priorities/priority`)
тепер вважаються однією лексичною родиною. Кілька різних можливих основ
(`axes → ax/axe/axis`) залишаються неоднозначними. Такі різні леми повертаються в `lemma_candidates`, мають
`ambiguous=true` й не підвищують загальний рівень.
Найнижча словникова оцінка зберігається навіть за відсутності контексту
для точного значення або частини мови. Це консервативна політика,
а не повноцінне визначення значення слова.

## Вирази та відсутність повторного підрахунку

Спочатку обирається найдовший вираз, потім раніший і найкоротший за розривом.
Для першого слова дозволена відома словоформа: `turn out → turned out`.
Підтримано два порядки для позначених розділюваних фраз:

```text
She turned down the offer.  -> компоненти: turned, down
She turned it down.         -> компоненти: turned, down; it рахується окремо
```

Для розриву дозволено до 4 токенів об'єкта: займенник або коротка група,
яка починається з артикля чи присвійного означення. Через межу речення
або очевидний сполучник розрив не допускається. Точні правила `turn down`
і `give up` зберігаються в `data/phrase_seeds.json`.

У GSE шаблони з одним внутрішнім `sth/sb/something/somebody/someone`
перетворюються на слот `{object}`: наприклад, `turn sth upside down`.
Складніші шаблони, альтернативи зі слешами й декілька слотів не
перетворюються на довільні регулярні вирази.

Знайдені лексичні компоненти вилучаються зі словесного підрахунку.
Об'єкт у розриві залишається окремою одиницею. `fragment` охоплює весь
фрагмент із розривом, але `token_indices` і `time_codes` містять лише
компоненти виразу. Розірвані вирази позначаються `ambiguous=true` через
можливість буквального прочитання. Деякі очевидно композиційні сполуки,
як `that is`, також не використовуються для підвищення рівня.

## Граматика

Замість незалежних пошуків `have been`, `be + ing` тощо аналізатор
читає послідовність:

```text
modal? -> have? -> been/be? -> being? -> lexical predicate
```

Підтримувані заперечення й прислівники можуть стояти між елементами.
Після читання ланцюжка його токени позначаються використаними: внутрішні
частини не створюють додаткового Present Perfect або Continuous.

| Фрагмент | Інтерпретація |
|---|---|
| That's annoying | Предикативний прикметник, не Continuous |
| That's disappointing | Предикативний прикметник, не Continuous |
| She is annoying me | Present Continuous, є прямий об'єкт |
| It must have been exciting | Один modal perfect + copular predicate |
| She has been working | Один Present Perfect Continuous |
| The letter has been written by her | Один Present Perfect Passive |
| She is going to work | Окремий шаблон going to |
| She has to work | Окремий шаблон have to |
| It may well have been exciting | Один ланцюжок із модифікатором may well, джерело C1 |
| She might as well have been working | Один ланцюжок might as well, без вкладеного Continuous |
| She seems to have written the letter | Perfect infinitive, джерело C1 |

Типові прикметники на `-ing` перевіряються окремо. Коли після них є
неоднозначне продовження, ознака лишається невпевненою. Відома прикметникова
форма на `-ed` без чіткої пасивної підказки теж має `ambiguous=true`.

Є обмежений пошук негативної інверсії на початку речення та кандидата
Third Conditional. Останній завжди неоднозначний без точного синтаксичного
розбору. Питальна інверсія, повний набір conditional, вкладені relative clauses,
еліпсис та всі 500 рядків CEFR-J **не реалізовані** як окремі детектори.

Додаткові правила `may well`, `may as well`, `might as well` посилаються
на рядки `131`, `130`, `133`. Вони теж поглинають внутрішній допоміжний
ланцюжок повністю. Активний perfect infinitive `to have written` має
джерело `90`; непідтримувані комбінації perfect infinitive залишаються без рівня.

Кожне правило має посилання на CSV, ID рядка, код, назву колонки,
початковий і нормалізований рівень. Приклад: Present Perfect Continuous
посилається на рядок `63`; заперечення — на `63-1`.
Рівень береться як мінімум із `CEFR-J Level`, `Core Inventory`, `EGP`, `GSELO`.
Колонка `FREQ*DISP` не є навчальним рівнем і не використовується.
Діапазон `B1-B2` дає B1; `B2.1` дає B2. Значення без CEFR пропускаються.
Якщо джерела для комбінації немає, її `level=null`, `ambiguous=true`:
складність не вигадується за довжиною допоміжного ланцюжка.

Лексичні та граматичні свідчення зберігаються незалежно. Заборона повторного
підрахунку компонентів фраз стосується лексики; граматична структура може
включати ті самі слова.

## Загальна оцінка

У числовій шкалі `A1=1, A2=2, B1=3, B2=4, C1=5, C2=6`.
Невідомі слова не отримують чисел. Упевненість `low/medium` є евристичною
ознакою достатності свідчень, а не ймовірністю правильності.

Для підсумку відкидаються неоднозначні збіги, записи без рівня
та, за замовчуванням, вибрані автоматичні оцінки.
Службові слова виключаються зі знаменника **лексичної складності**;
у загальній статистиці та лексичних результатах вони залишаються.

Лексична оцінка `L` — найвищий рівень, для якого є щонайменше 3 входження
змістових одиниць цього рівня або вище, що становлять щонайменше 7%
надійних змістових одиниць для A2–B1, 5% для B2 та 3% для C1–C2.
Для B2–C2 також потрібні щонайменше 3 різні леми/вирази. Це евристичні
пороги попереднього калібрування, а не офіційні пороги CEFR. Рахуються входження; вираз — одна одиниця.
За відсутності такого підвищення `L=1`.

Для кожного граматичного порога `k`:

```text
n_k = кількість надійних входжень рівня k або вище
d_k = 100 * n_k / кількість проаналізованих токенів
w_k = кількість різних 50-токенних вікон із такими входженнями
W = min(3, max(1, ceil(кількість токенів / 50)))

якщо n_k < 3: strength_k = 0
інакше: strength_k = min(1, d_k / 6) * min(1, w_k / W)

G = max(1, 1 + (k - 1) * strength_k для всіх k)
S = L + 0.75 * max(0, G - L)
```

`S` округлюється до найближчого рівня; половина округлюється вгору.
Одна складна конструкція не змінює результат. Часті складні конструкції,
розподілені по тексту, сильно впливають. Прості конструкції не знижують
лексичну складність. Вікна задаються токенами й не залежать від переносів
рядків або відсутності пунктуації.

У `ScoringConfig` можна змінити пороги, вагу граматики та включення
автоматичних оцінок. Повна конфігурація й проміжні частки повертаються
в `assessment`, тому результат можна пояснити й відтворити.

## Формат результату

| Поле | Зміст |
|---|---|
| `schema_version` | Версія контракту, зараз `1.0` |
| `assessment` | Рівень, числова оцінка, упевненість, частки й конфігурація |
| `statistics` | Токени, покриття, кількості та розподіли A1–C2 |
| `lexical_matches` | Леми/вирази, рівні, джерела, фрагменти й таймкоди |
| `word_levels` | Словник «нормалізоване слово або вираз → CEFR», невідомі слова мають `null` |
| `grammar_matches` | Правила, фрагменти, джерела та неоднозначність |
| `unknown_words` | Унікальні невідомі слова з частотами й `level=null` |
| `unknown_occurrences` | Усі їхні входження з позиціями |
| `automatic_matches` | Збіги, для яких вибрана мінімальна оцінка автоматична |
| `ignored` | Явно виключені входження |
| `sources` | Маніфест: URL, SHA-256, розміри й розподіли за словниками |
| `warnings` | Мала довжина, низьке покриття або недостатні свідчення |

У збігах `char_start` включний, `char_end` виключний. `token_indices`
є індексами нормалізованої послідовності, а не номерами рядків DataFrame.
`fragment` має нормалізовані пробіли. `time_codes` прибирає дублювання
одного вихідного рядка в межах одного збігу.
Розподіли включають також автоматичні й неоднозначні словникові оцінки;
для підсумку використовується тільки підмножина, описана вище.

`word_levels` дає компактне представлення словникових рівнів, наприклад:

```json
{"cats": "A1", "turned down": "B1", "zqxvbling": null}
```

Ключі — унікальні слова в нижньому регістрі у формі з тексту, а не леми.
Скорочення розкриваються відповідно до токенізації. Вираз повертається
одним ключем із його лексичних компонентів: `turned it down → turned down`,
а `it` залишається окремим словом. Компоненти виразу окремо не дублюються.
Явно проігноровані слова й числа не включаються. За конфлікту для однакового
ключа зберігається найнижчий рівень. Автоматичні та неоднозначні словникові
оцінки теж видимі в цьому словнику; їхні позначки залишаються у
`lexical_matches` і `automatic_matches`, а правила скорингу не змінюються.

## CLI для налагодження

```bash
python -m cefr_analyzer analyze --text "That's disappointing."
python -m cefr_analyzer analyze --file transcript.txt --ignore Alice --ignore "New York"
python -m cefr_analyzer analyze --words examples/words.csv --output result.json --json
python -m cefr_analyzer analyze --file transcript.txt --include-automatic
python -m cefr_analyzer calibrate --directory calibration_data --output reports/calibration_report.json
python -m examples.integration
```

`--words` приймає CSV або JSON-масив записів. У CSV значення `time_code`
залишаються рядками. Без `--text`, `--file` і `--words` читається stdin.
Стандартний вивід — короткий звіт; `--json` дає повну відповідь.
`--output` зберігає повну відповідь незалежно від формату stdout.
Код завершення: `0` — успіх, `2` — неправильні дані, файл або аргументи.

## Калібрування та межі застосовності

Команда `calibrate` використовує файли з рівнем у назві: підтримано як
`video_A1.txt`, так і `A1_daily_life.txt`. Суперечливі мітки в одній назві
викликають помилку. Поточна добірка містить 8 транскрипцій та 11 синтетичних
текстів; метрики повертаються також окремо за цими групами (суфікс і префікс
відповідно). Файли без CEFR-мітки пропускаються.
Порівнюються приблизні етикетки з результатом, обчислюються MAE у ступенях
CEFR і частка похибок не більше одного ступеня. Тексти не входять до
робочого аналізатора, у коді немає перевірок назв відео, самоназви рівня
або спеціальних правил для їхнього змісту.

У [calibration_report.json](../reports/calibration_report.json) збережено фактичні
результати. Ця мала добірка не є незалежним тестовим набором.
Наразі аналізатор занижує частину B2–C1 і завищує окремі A1–A2.
Змістова лексика, мінімальні рівні між значеннями та обмежене покриття
граматики не дозволяють точно відтворити всі мітки. Текстова транскрипція
також не містить темпу, акценту, чіткості мовлення та інших ознак аудіювання.

Для наступного етапу потрібні незалежні розмічені матеріали з різних тем,
ширше покриття граматики й окрема перевірка неоднозначних фраз. Поточні
обмеження явно відображені у звітах; `medium` не означає підтверджену точність.

Перевірки:

```bash
python -m unittest discover -s tests -v
```

Тести охоплюють обов'язкові приклади, словоформи, джерела мінімальних
рівнів, неоднозначність, невідомі слова, імена, переноси, часове зіставлення,
імпорт GSE/Kaikki, частоту складної граматики та CLI.
